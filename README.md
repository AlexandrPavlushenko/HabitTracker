# Курсовой проект №5

<i>Это DRF-проект трекера полезных привычек Habit Tracker</i>

## Описание проекта

## Установка:

1. Клонируйте репозиторий:

```
https://github.com/AlexandrPavlushenko/HabitTracker.git
```

2. Убедитесь, что Poetry установлен, если нет его нужно установить:
```
curl -sSL https://install.python-poetry.org | python3 -
```
Затем установите зависимости:
```
poetry install
```

3. Создайте и заполните данными файл <b>.env</b> по шаблону <b>.env.sample</b>, который находится в корне проекта
   Внимание! Переменной `ENV` задайте значение `local` для запуска проекта локально.<br>
4. Создайте и примените миграции

```
python manage.py makemigrations
python manage.py migrate
```

5. В проекте есть фикстуры для создания базы пользователей и привычек

```
   python manage.py loaddata users_fixture.json --format json
   python manage.py loaddata habits_fixture.json --format json
```
6. Создайте суперпользователя (опционально):

```
python manage.py createsuperuser
```
## Запуск в контейнере:
### Зависимости:
- Docker (должен быть установлен и запущен Docker Desktop)
- Docker Compose
### Установка:

1. Клонируйте репозиторий:
```
https://github.com/AlexandrPavlushenko/HabitTracker.git
```
2. Создайте и заполните данными файл <b>.env</b> по шаблону <b>.env.sample</b>, который находится в корне проекта
   Внимание! Переменной `ENV` задайте значение `docker` для запуска проекта в
   контейнере.<br>
3. Соберите и запустите контейнеры
```
docker-compose up --build
```
4. Примените миграции. Откройте новый терминал (или командную строку) и выполните:
```
docker-compose exec web python manage.py migrate
```

5. Создайте суперпользователя (опционально):

```
docker-compose exec web python manage.py createsuperuser
```
Теперь проект должен быть доступен по адресу http://localhost:8000/<br><br>
Документацию по работе с api можно изучить по адресу: http://localhost:8000/redoc/<br><br>
Для остановки контейнера выполните:
```
docker-compose down
```
Эта команда остановит и удалит контейнеры, но не удалит образы.
### Полезные советы
 Для просмотра логов всех сервисов в реальном времени, используйте:
```
docker-compose logs -f
```
Вы также можете проверить статус ваших контейнеров с помощью:
```
 docker-compose ps
 ```
## Деплой на удаленный сервер

### Настройка удаленного сервера

1. **Подготовка сервера**:
   - Убедитесь, что ваш сервер запущен на базе Ubuntu (или другой Linux-дистрибутив).
   - Установите [Docker](https://docs.docker.com/engine/install/) и [Docker Compose](https://docs.docker.com/compose/install/) на удаленном сервере:
```
bash
     sudo apt update
     sudo apt install docker.io docker-compose
```   

2. **Настройка SSH-доступа**:
   - Настройте SSH-доступ к серверу, чтобы вы могли подключаться к нему без ввода пароля (с помощью SSH ключей).

3. **Клонирование репозитория на сервере**:
   - Подключитесь к удаленному серверу через SSH и выполните:
```
bash
     git clone https://github.com/AlexandrPavlushenko/HabitTracker.git
```    

4. **Создание файла `.env` на сервере**:
   - Скопируйте или создайте файл `.env` на сервере, заполнив его необходимыми переменными окружения.

### Деплой приложения:

1. **Сборка и запуск контейнеров**:
```
bash
   docker-compose up --build -d
```
   - Запустите приложение в фоновом режиме.

2. **Примените миграции**:
```
bash
   docker-compose exec web python manage.py migrate
```  

3. **Создание суперпользователя (опционально)**:
```
bash
   docker-compose exec web python manage.py createsuperuser
```  

Теперь ваше приложение должно быть доступно по IP-адресу вашего сервера.
.

### Полезные советы:

- **Для просмотра логов всех сервисов в реальном времени**:
```
bash
    docker-compose logs -f
```
    
  
- **Проверьте статус ваших контейнеров**:
```
bash
    docker-compose ps
```
    

### Возможные проблемы и их решения:

- **Контейнер не запускается**: Убедитесь, что Docker и Docker Compose установлены и работают правильно. Проверьте логи с помощью команды `docker-compose logs`.

- **Ошибка миграций**: Проверьте, правильно ли заполнен файл `.env`, и убедитесь, что база данных доступна.

- Если у вас возникают проблемы с доступом, убедитесь, что приложение запущено и не заняты порты 8000 или 80 другими процессами.
# CI/CD Pipeline
Проект использует GitHub Actions для автоматизации процессов:
- Линтинг кода
- Тестирование
- Сборка Docker-образа
- Деплой на сервер

## Этапы выполнения:
### Линтинг (Lint)
- Запускается при каждом push и pull request
- Использует Python 3.12
- Устанавливает Poetry с виртуальным окружением в проекте
- Кеширует зависимости
- Проверяет код с помощью flake8

### Тестирование (Test)
- Зависит от успешного линтинга
- Устанавливает все зависимости проекта
- Выполняет миграции базы данных
- Запускает юнит-тесты Django

### Сборка (Build)
- Зависит от успешного тестирования
- Собирает Docker-образ с тегом, содержащим хеш коммита
- Пушит образ в Docker Hub

### Деплой (Deploy)
- Зависит от успешной сборки
- Подключается к серверу по SSH
- Останавливает текущий контейнер
- Запускает новый контейнер из свежего образа

## Требования к окружению
### Секреты GitHub (добавить в Settings → Secrets):
- DOCKER_HUB_USERNAME - логин Docker Hub
- DOCKER_HUB_ACCESS_TOKEN - токен доступа Docker Hub
- SSH_KEY - приватный SSH-ключ для доступа к серверу
- SSH_USER - пользователь сервера
- SERVER_IP - IP-адрес сервера

### Сервер:
- Установленный Docker
- Разрешенный SSH-доступ
- Открытый 80 порт (для веб-доступа)

Активация пайплайна осуществляется автоматически при пуше или пул-реквесте на GitHu
